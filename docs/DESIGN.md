# 設計（VAL Tracker）

Riot アカウントと連携する VALORANT のトラッカー。サイト一覧（Home Page）に Python のサイトとして載る。
書式・CI・サイトの約束は統括の [CONVENTIONS.md](https://github.com/AlstRafe/home-page/blob/master/docs/CONVENTIONS.md) に従う。

## 作り

- サーバー: Python（Flask）。`valtracker/` パッケージ。Home Page のサーバーが `valtracker.hosting:site` を読み込み、
  `/val` の下で配信する。単独でも `python -m valtracker` で動く（このPCでの確認用）
- 画面: サーバーで HTML を組み立てる（Jinja テンプレート）＋小さな素の JS（お気に入り・テーマ・読み込み中の表示）。
  npm は整形・チェックの道具だけ
- 4 言語（ja / ko / en-GB / zh-TW）、ダーク / ライト、スマホ幅（760px 以下）は下のタブバー
- 外部の CDN・フォントは読まない。エージェントやマップの画像もサーバーが取ってきて `instance/` にためて自分のアドレスで出す

ヘッダーのタブは 検索・ランキング・ショップ・エージェント・ツール の 5 つ。持ち主にはもう 1 つ「ライブ」（検索の次）が出て、
ライブと進み具合はその中、所持品はショップの中、設定はツールの中から開く。ライブのタブの点は、どのページでも持ち主の
ゲームの状態（メニュー・マッチング中・エージェント選択・試合中）を表し、エージェント選択が始まると画面の下に知らせが出る
（`/val/live/state` を開いている間だけ数秒ごとに読む。2026-11-06、ショップの中では見つからないと言われて）。

2026-11-12、「試合が始まってからピックになるまでが遅い（DailyVal はマッチ開始の 5 秒カウントから）」「ピックの画面の
読み込みが遅い」と言われて:

- 読む間隔は場面ごと（`live.EVERY`）。試合が見つかったら毎秒、マッチング中とエージェント選択は 2 秒ごと、それ以外はゆっくり。
- パーティーの State が `MATCHMADE_GAME_STARTING`（5 秒カウント）になったら、セッションがまだメニューでもエージェント
  選択（pregame）をすぐ読む。まだ無ければ「試合が見つかりました」を出し、ほかのページでも知らせる。
- 1 回の読み取りで Riot に聞くのは 1〜2 回（セッションと、前回のパーティーかエージェント選択）。名前は 1 人 1 回、ランクは
  待つのは 0.8 秒まで（残りは次の読み取りで）、自分のエージェントはマッチング中に 1 回だけ読んでおく（所持品 10 回は読まない）。
  すべてこのサーバーから Riot に聞くので、持ち主の PC の VALORANT には何も足さない。
- 画面は変わったところだけ差し替える（app.js `morph`）。エージェントの絵は作り直さない。絵は小さい方（128 px）で、
  マッチング中にブラウザーに読んでおき、`/media` は `Vary: Cookie` なし（クッキーが変わるたびに読み直されていた）。

## ほかのトラッカーとの比べ（2026-11-06）

Tracker.gg・DailyVal・blitz などにあって足した物、どこにもないので足した物、まだの物。

- 足した: KAST・FK/FD・クラッチ・マルチキル・設置/解除、エージェント・マップ・武器別の成績、RR の推移と次のランクまで、
  ラウンドの流れとキル、対面の成績、パーティ、地域のランキング、ショップ（ナイトマーケット・持っている物の印）、
  クロスヘアのコード、サーバー状況
- どこにもない物として足した: 同じロビーの平均との比べ（自分が上か下か）、よく組む人（勝率つき）、
  クロスヘアを暗い所と明るい所で並べて見る、ショップで持っている物に印、4 言語で全部、
  サーバーごとの混む時間帯と待ち時間の目安、いま出るマップ、パーティーのランク差の確認、今日の勝敗と RR、
  いまの勝率でランクアップまで何試合、アクト終了・毎日のスキンの入れ替わりまでの時間、tracker.gg の URL を貼っても検索
- DailyVal にある物（2026-11-06 に足した）: スキン図鑑（動画・バリエーション・評価）、ストアの履歴と欲しい物の印、
  ナイトマーケットをめくる、ストアの入れ替わりのカレンダー、バトルパス・契約・ミッション、いまの試合（キュー・ピック・確定）、
  所持品から装備、ニュース、eスポーツ、エージェントの使用率と勝率、プレイヤー同士の比べ、戦績の画像、試合のマップ絞り込み、
  クロスヘアの保存
- DailyVal にあって足さない物: コミュニティ・チャット・グループ（アカウントと見回りが要る）、フレンドのオンライン
  （Riot のチャット XMPP が要る）、
  プロの設定・定点の動画（確かな出どころがない）
- tracker.gg にある物（2026-11-06 に足した）: 1000 点のスコア（tracker.gg の Tracker Score にあたる）と S〜D の評価、
  数字ごとの「上位 X%」、スコアの推移。tracker.gg と違い、物差しは**同じランク帯**の試合（このサイトが見た試合の、
  名前を持たない 1 人 1 行。`activity.py` の `lines`）で、出し方（ACS 30・KAST 25・DDΔ 25・勝ち 20）を画面に書く。
  200 行（`LINES_ENOUGH`）に満たないうちは出さない（`score.py`）
- tracker.gg にあって足さない物: プレミアのチームのページ（HenrikDev の答えの形を確かめられない）、定点（Lineups）と
  クリップ（確かな出どころがない）、LFG（アカウントと見回りが要る）、オーバーレイ（ブラウザーでは動かない。
  いまの試合のページが代わり）
- あとから足した（2026-11-06）: マップごとの得意エージェント、エージェント選択でのマップ別勝率（持ち主）、
  ランクの分布（`/val/ranks`。このサイトが見たコンペの 1 試合 1 人ずつの行から。地域ごと、各ランクが上位何 %、
  戦績にも「この地域で上位 X%」。100 行に満たない地域は出さない）
- キルとデスの場所（2026-11-06。tracker.gg のヒートマップにあたる）: HenrikDev v4 のキルにある倒された場所
  （`location`）とキルした人の立ち位置（`player_locations`）を、valorant-api.com のミニマップと換算の数
  （`xMultiplier` など）で点にする（`heatmap.py`）。戦績ではマップごと、試合では線つき。攻撃・防衛とキル・デスで
  絞れる（スクリプトなし、`:has`）。tracker.gg より進めた所: 点をいちばん近いコールアウトの名前にまとめ、場所ごとの
  キル・デス・ファーストデスの表と「ここで負けやすい」を出す
- シーズン別の成績（2026-11-06。tracker.gg の Season stats にあたる。`/val/p/<名前>/<tag>/seasons`）: Riot は過去の
  アクトの成績を公開していないので、HenrikDev の保存済み試合（v1 stored-matches、モードごと）から数える
  （`seasons.py`）。アクトごとの勝率・K/D・KDA・HS率・ADR・ACS・DDΔ・平均キル・最高ランク・よく使ったエージェント。
  tracker.gg より進めた所: 前のアクトからの変化を数字ごとに出す。全部の試合ではないので、数えた試合数を書く。
  戦績のページのリンクから開いたときだけ HenrikDev に聞く（30 分覚える）

- 通算（2026-11-06。tracker.gg の Lifetime にあたる。`?span=all`、比較も）: このサイトが読んだ試合を全部
  `instance/archive.sqlite` に持つ（`archive.py`。1 試合 1 行、henrik の形を zlib で）。中身は (1) HenrikDev で読んだ
  試合（戦績・試合のページ）、(2) 通算を開いた人の Riot の試合履歴（PD の match-history → match-details、持ち主の
  連携で。2.5 秒に 1 回、裏で。429 は 2 分休む）と RR（competitiveupdates）、(3) Riot が使えないときだけ HenrikDev の
  古いページ、(4) Riot がもう持たない古い試合は HenrikDev の保存済み試合（ラウンドがない「簡単な記録」: KAST・FK・
  武器・場所には入れず、画面に何試合かを書く）。PD の試合は本人以外の名前を消す（隠している人かが分からないので）。
  20 分たって開くと新しい試合だけ読み直す。点数の推移は 40 点、RR の点は 60 個、キルの場所の点は 800 個まで

- アクト（2026-11-12。tracker.gg が既定で見せる「今のアクト」の数字。`?span=act&act=<uuid>`、比較も「今のアクト」）:
  通算と同じ保存した試合を、valorant-api.com の seasons にあるアクトの始まりと終わりで絞る。アクトは最初に保存した
  試合のアクトから今のアクトまで選べる。まだ読み込んでいる途中なら、通算と同じく途中までの数だと書く
- 数字の並び（2026-11-12。tracker.gg の Overview にあたる）: 大きい 4 つ（ダメージ/ラウンド・K/D・HS率・勝率）に
  同じランク帯での位置（棒と「上位 X%」）。前は ADR の横の「下位 X%」が ACS の、DDΔ の横の「上位 X%」が KAST の
  順位で、読み違えるので、順位は数字ごとに付ける。ほかに ACS・KAST・DDΔ/ラウンド・KAD・キル/ラウンド・キル/デス/
  アシストの合計・ファーストキル/デス（ラウンドの何 %）・クラッチ（挑戦と成功率）・エース（4K/3K/2K）・フローレス
  （味方が誰も倒されずに勝ったラウンド）・最多キル（その試合へのリンク）・経済効率（1000 クレジットあたりのダメージ）。
  クラッチの挑戦・フローレス・キルの距離は `rounds.extras` が保存済みのキルの並びから出すので、前に保存した試合にも付く
- ほかに tracker.gg 並みにした所: クラッチを相手の人数ごと（1v1〜1v5 の成功/挑戦）、ロール別、エージェント表に
  時間・DDΔ・KAST、マップに K/D・ACS・ADR、命中部位に発数、武器ごとのキルの距離（平均と最長。倒した位置と倒された
  位置の床の上の距離で、高さは入らない）。試合の行は K/D/A・K/D・ADR・ACS・HS・スコアを名前つきの欄にして縦にそろえ、
  MVP でない試合は順位（3位）、日ごとの見出しに K/D。グラフはスマホ用にも描き（800×150 のままだと 65px の高さで
  文字 5px だった）、最初と最後の日付を下に書く

eスポーツの日程は Riot の公式サイト（valorantesports.com の日程のページ。ブラウザー用に今後 40 試合ほどが HTML に
入っている）から読み、来なければ HenrikDev。結果と試合中のスコアは公式サイトのページにない（Riot の API はキーが要る）
ので HenrikDev から読み、読めないときはエラーにせず公式サイトへ案内する。

Riot の PD・GLZ（契約・パーティー・キュー・エージェント選択とピック・試合中・名前・装備の PUT）の答えの形も公開されていないので、ない物は出さない
読み方にしている。本番で持ち主が開いて違ったら `riot.py`・`progress.py`・`live.py` を直す。

HenrikDev の答えの形（ラウンド・キル・ランキング・お知らせ・ストア）はこの環境から確かめられないので、v4 と v2 の
両方の名前を読み、ない物は出さないだけにしている。本番で形が違ったら `henrik.py` と `rounds.py` の読み方を直す。

## 混み具合と待ち時間（`valtracker/activity.py`）

Riot も HenrikDev も接続人数・待ち時間を出さない（2026-11-05 時点）。なのでこのサイトが見た試合から目安を出し、
画面にそう書いて、何試合から出したかも出す。

- 見た試合（戦績・試合のページ、裏の収集）ごとに 1 行: 地域・サーバー（`cluster`）・モード・開始・長さ・平均ランク。
  名前や ID は持たない。`instance/activity.sqlite`、28 日で消す。数えるのは 14 日
- 混み具合 = その時間に始まった試合の割合（平均の時間の 1.3 倍以上で「混んでいる」、0.7 倍以下で「空いている」）。
  48 試合（`ENOUGH`）未満のサーバーは「まだ試合が少ない」とだけ出し、混む時間は言わない
- 待ち時間 = 同じ人の続けての 2 試合の「前の終わり → 次の始まり」（30 秒〜20 分、同じモード）。マッチング＋
  エージェント選択＋読み込み。6 件未満は出さない
- 1 試合の長さ = モードごとの試合の長さの中央値（6 件から）
- 時刻は見る人の時計: ページのスクリプトが UTC からの分を `tz` クッキーに入れる。ないとき・言語の時計と同じときは
  言語の時計（ja: 日本時間、ko: 韓国時間、zh-TW: 台湾時間、en-GB: UTC）
- 裏の収集: 240 秒に 1 人（`VAL_COLLECT_SECONDS`、0 で止める）、見た試合の人から、呼んだ回数の少ない地域・件数の少ないランク帯を先に。
  最初はランキングの人から。HenrikDev のキーと呼べる回数はページと同じ
- 中国大陸版（无畏契约）は Tencent の別のサーバーで、外から戦績を読む方法がないので調べられない。ツールに案内

要るので HenrikDev を使う。HenrikDev のニュースは言語によって古いまま止まることがある（2026-11: 日本語が 12.04 のまま）。

## データの持ち方

- `instance/`（Git に入れない）: 設定（API キーなど）、外部 API の答えの一時保存、画像のキャッシュ
- お気に入り: 見ている人のブラウザ（localStorage）。登録なしで使える
- 外部 API の答えは数分ためて、同じ人を何度開いても呼びすぎない（HenrikDev のキーは呼べる回数に上限がある）
- eスポーツの日程は、新しいのが来ないとき（混み合い・時間切れ）は最後に来た日程を 1 日まで出し、いつのものか書く。
  失敗のあとはしばらく聞かない（1 回に最大 7 回呼ぶので、混み合いが続く元になっていた。2026-11-06 の本番確認）
- Riot のログイン情報（段階2）は持ち主の分だけ、`instance/riot.json`（持ち主だけが読める）にだけ置く

## Riot のログイン（段階2、`valtracker/riot.py`）

Riot のサインインにはキャプチャがあるので、パスワードはサーバーに渡さない（2026-11-05 に持ち主が決定）。

1. 持ち主が PC のブラウザで Riot にログインし（「サインインしたままにする」）、開発者ツールで auth.riotgames.com の
   `ssid` クッキーを写して `/val/settings` に貼る（Cookie ヘッダーまるごとでもよい）
2. サーバーは要るたびに ssid で `auth.riotgames.com/authorize` を開き、1 時間のトークンを受け取る。Riot が返す新しい
   ssid（Set-Cookie）で保存し直すので、パスワード変更やログアウトまで貼り直さなくてよい
3. エンタイトルメントのトークン・puuid（userinfo）・シャード（riot-geo）を取り、PD の財布・ロードアウト・所持アイテム
   （種類ごと）を読む。90 秒ためる
4. 切れたら設定と所持品のページで「ログインが切れています」と出し、ssid は残す（もう一度通ることがある）

ログイン後に移ったアドレス（`playvalorant.com/opt_in#access_token=…`）を貼っても 1 時間だけ使える。
PD の答えの形は公開されていないので、読めなかったものは設定ページに「最後に読めなかったもの」として出す。

## PC アプリ（`valtracker/desktop.py`・`valtracker/localclient.py`）

2026-11-12、持ち主の頼み（「VALORANT には影響を大きく与えないことが絶対条件」）。

- 形: サイトの Flask アプリをこの PC の 127.0.0.1（空いているポート）で動かし、pywebview の WebView2 ウィンドウで開く。
  画面・4 言語・テーマはサイトのものそのまま。Electron のように Chromium を抱えず、Windows に入っている Edge の部品を使う
- ログイン: Riot クライアントの lockfile（`%LOCALAPPDATA%\Riot Games\Riot Client\Config\lockfile`）のポートとパスワードで
  ローカル API の `/entitlements/v1/token`（トークン）・`/chat/v1/session`（Riot ID）・
  `/product-session/v1/external-sessions`（VALORANT の起動・シャード・クライアントの版）を読む。パーティーのサーバーの
  地域は VALORANT のログ（`glz-<地域>-1.<シャード>`）から。riot.py はこれがあれば ssid より先に使う
- 速さ: ローカル API の websocket で自分のプレゼンス（MENUS / PREGAME / INGAME、パーティーの状態
  `MATCHMADE_GAME_STARTING`）、起動・終了、Riot のプッシュ（ares-parties / ares-pregame / ares-core-game）を受け、
  `/live/next`（ロングポーリング、25 秒）でページに伝える。ページは知らせが来たらすぐ読み直す（いつもの間隔の読み直しも残す）。
  GLZ の session は聞かない（プレゼンスでわかる）。ゲームが閉じていれば Riot には何も聞かない
- 負荷: 優先度「通常以下」＋効率モード＋メモリ優先度低、WebView2 は `--disable-gpu --force-prefers-reduced-motion`、
  ウィンドウが隠れている間は何も読まない、前面に出ない、活動の収集（`VAL_COLLECT_SECONDS`）は 0
- 守り: 127.0.0.1 だけで待ち、Host が自分のアドレスでない要求は 403（DNS リバインディング）。二重起動しない（ミューテックス。
  2 度目の起動は、題名と WinForms のウィンドウクラスで自分のウィンドウを見つけて前に出すだけ。アプリが自分から前に出るのは
  このときだけ）
- 確かめていないこと（コンテナからは Riot クライアントに届かない）: プレゼンスの形（2024 年以降の入れ子と以前の平らな形の
  両方を読む）、external-sessions の `-ares-deployment`、Riot のプッシュの `uri`。読めなければサイトと同じく GLZ に聞く
- 枠のないウィンドウ（2026-11-12、「UI とか改善余地ある」「機能もね」）: pywebview はブラウザのキー（F5・Alt+←）と右クリック
  メニューを切り、`target=_blank` だけをいつものブラウザに渡し、ダウンロードは捨てる。なので app.js（`body.app`）が戻る・進む・
  読み直しをボタンとキーで持ち、ほかのサイトのリンクに `target=_blank` を付ける。desktop.py は `ALLOW_DOWNLOADS`（保存の
  ダイアログ）、閉じるときのウィンドウの位置と大きさ（`window.json`、WinForms の `RestoreBounds`。開くときは画面より
  大きくしない: 1366×768 や 150 % 表示でも収まる）を持つ。人に渡すアドレス（共有・クロスヘアのリンク・カレンダー）は
  `shared_url` で公開サイトのものに
- 新しい版の知らせ（2026-11-13）: リポジトリは非公開なので、GitHub のリリースはログインなしだと 404（#38 の「リリースの
  `target_commitish` と比べる」は一度も働かなかった）。代わりに公開サイトが `/app/latest` で「アプリの元になるファイル
  （desktop.yml の `paths`）を最後に変えたコミットとその時刻」を答える（`release.py`、VM のクローンに `git log -1 -- …`、
  5 分に 1 回まで）。desktop.yml は同じ関数でビルドに印を付ける（`python -m valtracker.release valtracker/BUILD`、
  `fetch-depth: 0`）。アプリは 2 つを比べ、サイトのほうが新しく、そのコミットから 20 分たっていれば（ビルドとリリースが
  終わっている）知らせる。リンクはいつもリリースのページ（答えの中身は開かない）
- ライブ（サイトも同じ）: 960px 以上でエージェント選択は味方（その下に構成の目安）とピックを半分ずつ横に並べ（勝率は角）、
  対戦中は両チームを横に並べる。この 2 つの間（`.live-wide`）はページを窓の幅いっぱい（86rem まで）に広げ、行を詰め、
  見出し・「VALORANT: …」の行・手順の箱・説明を出さない（説明はゲームが閉じている間とメニューにある）。実際の人数
  （味方 5 人に今アクトの成績、29 体、対戦中 10 人）で測ると #38 の 4:7 では味方が 950px まで伸びていた。いまは 1164×681 の
  窓（1366×768 の画面）でも全員とピックが収まる。確かめ方: `tests/ui/serve.py` は満員のロビーを作る
- 試合直後の結果（2026-11-13）: 対戦中に覚えた試合 ID の match-details と competitiveupdates を PD から読み、ライブに
  プレイヤーページの試合の行と同じ形で出す（`owner._last_result`）。HenrikDev を待たず、キーも要らない。Riot の記録は全員の
  名前を持つが、出すのは自分の行だけ。12 秒おきに 8 回まで聞き（射撃場は記録がない）、読めたら通算（archive）にも入れる
